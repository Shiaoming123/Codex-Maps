# Codex Maps 产品简报

## 1. 一句话愿景

把分散在列表里的 Codex Session 变成一张有层级、有状态、有关系的工作地图，让用户能在几秒内回答：什么正在做、什么需要我、什么已经完成、它从哪里分支出来、下一步该打开哪一个 Session。

## 2. 为什么是“地图”

现有 Session 列表主要解决“进入聊天”，但当项目和并行任务增多后，用户还需要解决四类问题：

- 定位：标题相近、项目众多时，快速找到正确 Session。
- 判断：区分正在执行、等待输入、空闲、失败与真正完成。
- 理解：看到当前计划、最近输出、上下文消耗和子 Agent。
- 关系：知道 Fork、子 Agent、父 Session 和派生任务之间的来源。
- 管理：重命名、置顶、归档、恢复、删除和项目归属。

“地图”不是第一版就做复杂节点图，而是先建立稳定的信息层级和关系模型。一级页负责扫视与管理，二级页负责解释单个 Session；关系图在数据可靠后再增强。

## 3. 产品形态

### Codex 内嵌页（目标形态，当前受宿主 API 阻塞）

Codex 左侧提供独立入口，打开完整的 Codex Maps 一级页。用户不离开主要工作壳即可查看和管理 Session，并可跳回原 Session。

### 独立管理器 / 副屏页

独立窗口复用同一套 UI，可放到副屏持续显示状态、等待输入和完成提醒。Codex Maps 自己拥有 App Server 时可以提供实时和管理能力；Codex Desktop 已拥有源但未开放共享 Bridge 时，独立页必须降级为只读并把活跃状态标为未知，不能维护第二份“伪实时”状态。

### 两级信息架构

```text
一级：Session 地图
  ├─ 搜索、筛选、项目、置顶、归档
  ├─ 运行中 / 等待 / 失败 / 今日完成
  └─ 需要关注与最近事件

二级：Session 详情
  ├─ 当前计划与进度
  ├─ 最近输出、Token 与上下文窗口
  ├─ 子 Agent、Fork 与父子关系
  └─ 重命名、归档、删除、在 Codex 中打开
```

### 可视化语法

- **项目泳道图（一级默认）：** 每个项目是一条稳定泳道，Session 是按更新时间和派生关系排列的节点。它用于快速扫视项目负载、运行状态和需要处理的节点；列表与卡片仍作为密集信息和无关系数据的降级视图。
- **Session 关系树（二级按需）：** 以当前 Session 为根，向下展示子 Agent、用户 Fork 和二次派生。它用于回答“从哪里分出来、现在各分支做到哪里”。
- **阻塞鱼骨图（MVP+1）：** 只对等待、阻塞或失败的 Session 展示，把明确事件归入输入/审批、工具/环境、外部依赖、计划/范围等原因。它用于诊断“为什么卡住”，不承担 Session 导航。

三种视图共享同一组节点语义：标题、项目、执行状态、目标状态、最近活动、关系摘要；只有存在权威关系或原因字段时才画连线，缺失时明确降级而不是根据聊天正文推断。

## 4. 状态必须可解释

Codex Maps 使用两个状态轴，避免把一次回复结束误判成整个任务完成。

| 状态轴 | 典型值 | 回答的问题 |
|---|---|---|
| 执行状态 | 运行中、等待输入、空闲、失败、未知 | Agent 此刻在做什么？ |
| 目标状态 | 进行中、暂停、阻塞、完成、已归档、未声明 | 这项工作整体完成了吗？ |

`turn/completed` 只把执行状态从运行中转为空闲；只有明确的目标完成状态或用户显式标记，才能显示“目标已完成”的勾选。数据缺失时显示“未知/未声明”，不猜测。

## 5. MVP 范围

### 当前可交付 MVP 必须完成

- 读取、分页、搜索和按 cwd/project、置顶、归档、状态筛选 Session。
- 在 Codex Maps 拥有 App Server 的模式中实时订阅运行状态、Turn、计划、等待审批/输入、错误和 Token 事件；其他 owner 下明确降级。
- 一级项目泳道地图（含列表降级）和二级详情可用，空状态、加载、断线和错误状态完整。
- 重命名、置顶、归档、恢复、永久删除可用。
- 删除前展示根 Session 与所有 spawned descendants，并要求强确认。
- 一个运行实例内的所有 Codex Maps 页面共享同一个事件源和 Session Store。
- 只在宿主能返回 exact thread id 回执时显示“在 Codex 中打开”。
- Windows x64 上完成一条端到端真实 Session 验收链。

### MVP 中展示、编辑延后

- 项目名称、图标、颜色、排序和多个根目录：能力存在时读取展示。
- Fork/子 Agent：二级页先以列表和数量展示；关系字段可靠时可展示两层只读关系树，复杂自动布局后置。
- 阻塞鱼骨图：保留入口和信息结构，待原因字段与事件归因可靠后实现。
- 最近输出：先显示权威的最后一条 Agent 输出摘录，不调用模型生成摘要。

### 明确不进入 MVP

- 云同步、多人协作、账号体系和远程管理。
- 全量 transcript 本地索引或第三方上传。
- 复杂图谱布局、拖拽改写父子关系、跨 Session 合并。
- Token 成本预测、团队统计和长期分析看板。
- 对所有 Codex Desktop build 的无条件兼容承诺。
- 在没有公开挂载 API 时修改 Codex MSIX/ASAR、注入 minified renderer，或宣称存在原生左侧入口。

## 6. 产品原则

1. 权威优先：App Server 是 Session 事实来源，本地只保存 UI 偏好和明确的用户补充标记。
2. 先可用再丰富：先跑通一个真实 Session 的完整链路，再增加复杂关系图。
3. 同源实时：任何可见窗口都从同一个规范化 Store 读取。
4. 破坏性操作显式：归档可恢复；删除会级联时必须展示影响范围。
5. 未知即未知：Token、关系、目标状态缺失时不伪造。
6. 宿主可替换：UI 和领域模型不依赖 Windows 路径或 Codex renderer DOM。

## 7. MVP 成功标准

- 用户能在 10 秒内从一级页找到一个需要关注的 Session，并打开其详情。
- Session 进入执行、等待输入、完成当前 Turn、失败时，两个窗口在可感知延迟内一致更新。
- 任一窗口断开重连后，以权威快照恢复，不遗留“假运行中”状态。
- 五类核心管理操作均有成功、失败和取消的可验证反馈。
- 永久删除无法通过单次误点击触发，且影响范围与 App Server 实际级联一致。
- Codex build 不兼容时，内嵌扩展拒绝加载并保留独立诊断入口。

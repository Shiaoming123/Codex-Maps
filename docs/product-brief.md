# 产品简报

## 1. 问题定义

当 Codex Session 数量增加后，左侧列表很难承担“检索、理解、分组和回看”四种任务：标题不一致、项目上下文不明显、已完成任务与活跃任务混在一起、历史任务缺少稳定的入口。用户真正需要的是一个更直观的可视化管理层，而不是另一个会复制 Session 数据的聊天窗口。

## 2. 产品目标

- 用一个搜索框快速找到历史 Session。
- 按项目路径、状态、归档状态、最近使用时间筛选。
- 用项目、分组和颜色降低扫描成本。
- 所有批量操作都可预览、可确认、可回退。
- 不破坏官方 Codex 安装，也不把个人 Session 数据提交到公开仓库。
- 在独立 UI 稳定后，提供 Windows 私有 Codex 壳层/侧栏增强。

## 3. 非目标

- 不做云端 Session 同步、账号体系或多人协作。
- 不把 Codex 对话全文上传到第三方服务。
- 不直接编辑 Codex JSONL/SQLite 作为默认数据通道。
- 不把“普通 Codex 插件 manifest”描述成官方原生左侧栏扩展 API。
- 不在第一版承诺兼容所有 Codex Desktop 版本。

## 4. 用户故事

1. 我想搜索“Blog”并按最近使用排序，快速回到正确任务。
2. 我想只看当前项目的活跃 Session，不被归档历史干扰。
3. 我想把完成的任务移动到 DONE 分组，但在执行前先看到变更清单。
4. 我想给项目设置别名和颜色，但这些偏好不应改变 Codex 的权威 Session 内容。
5. 我想尝试内嵌侧栏，但官方 Codex 更新后失败时仍能回退到独立窗口。

## 5. 产品分层

```text
权威数据层：codex app-server
  ├─ thread/list / thread/read / thread/archive
  ├─ project/* 与 threadSection/*（实验能力，需版本探测）
  └─ 事件流：thread/status/changed、turn/*、item/*

本地偏好层：仅保存 UI 语义
  ├─ 别名、颜色、视图布局、筛选器
  └─ 不保存完整 transcript，不复制原始 Session 存储

客户端层：独立管理器 → Windows 私有壳层
```

## 6. 成功标准

### MVP

- 在本机启动 app-server 并完成 initialize 握手。
- 能列出最近 Session，支持搜索、项目 cwd、归档筛选和 JSON 输出。
- app-server 不可用时给出明确错误，不静默回退到猜测或直接读取私有存储。
- 公开仓库扫描不包含凭据、Session 正文、个人截图和本机路径快照。

### 侧栏阶段

- 官方 Codex 保持可启动且不被覆盖。
- 私有副本有独立用户数据目录。
- 补丁版本不匹配或注入失败时自动回退到独立管理器。
- 至少完成一次 away-and-back、归档/恢复和新版本重建验证。
